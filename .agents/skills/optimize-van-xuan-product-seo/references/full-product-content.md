# Full product SEO content contract

Create one complete pack for every included product. Exclude categories or
products the owner explicitly removes from scope.

## Required deliverables

1. Primary search intent and one main topic; add secondary topics only when the
   page can answer them naturally.
2. Unique SEO title and meta description that accurately preview the page.
3. Unique short description that identifies the product and its most useful
   verified differentiator.
4. A people-first long description with a natural opening and only the sections
   supported by evidence. Common sections include product identity, verified
   ingredients/process, sensory profile, volume/alcohol variants, suitable use
   context, serving/storage, purchasing guidance, and responsible use.
5. Useful alt text for the primary product image and meaningful gallery images.
6. Canonical URL, internal-link targets, and Product/ProductGroup mapping that
   match visible product and SKU data.

## Volume source rule

Use the volume already stored in the product name, SKU, or variant attributes.
Keep that value consistent across the SEO title, meta description, short and
long descriptions, image alt text, variant/offer mapping, and structured data.
Do not replace an existing volume with a competitor's value. If name, SKU, and
variant data disagree, mark the product blocked until the owner confirms the
correct volume.

## Depth rule

Do not target an arbitrary word count. Write enough original information to
answer supported purchase questions, and stop before repetition begins. A short
description may be concise; the long description must not be a renamed database
record, a three-bullet stub, or generic boilerplate shared across products.

If verified facts are too sparse for a useful page, mark the product `blocked`
and request a compact fact sheet from the owner. Do not publish a thin page just
to complete a batch.

## Public-copy rule

Write for the shopper. Keep these items only in the internal review manifest:

- uncertainty and missing-fact notes;
- prompts to the owner or editor;
- field names and database language;
- SEO rationale, keyword notes, and schema instructions;
- statements that ask the shopper to verify facts the merchant should provide.

Commercial values that change frequently—price, stock, discounts, SKU, and
delivery terms—should render from structured product fields rather than being
duplicated in prose.

## Review table

For every product, preview: immutable ID, inclusion status, evidence, blockers,
topic, SEO title, meta description, short description, full HTML description,
image alt, internal links, structured-data type, and intentionally unchanged
fields. Require explicit approval before writing.
